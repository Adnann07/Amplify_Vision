# Spacecraft Model Sources

NASA's actual `NASA-3D-Resources` repository tree was checked before integration. All newly used model files are stored locally under `public/models/`; model source links point to the verified source folders. NASA's repository README describes its assets as free and without copyright and links to NASA media usage guidance. That general repository statement is not an assertion of NASA endorsement.

## Asset details and use

- **Voyager:** NASA's `Voyager.zip` contains spacecraft-specific STL parts including the bus, high-gain dish, boom segments, instruments, and appendages. The downloaded STL geometry is loaded with Three.js `STLLoader`. Parts are placed in an approximate assembled pose for viewing; NASA's source meshes are not presented as an engineering-accurate, ready-assembled CAD model.
- **Cassini:** NASA's `Cassini.zip` contains spacecraft-specific STL parts and an assembly reference image. The viewer uses the NASA bus, dish, boom, Huygens, and RTG geometry with an approximate assembly layout.
- **Europa Clipper:** NASA's Version 2025D page identifies the model as a printable scale model and links three STL parts. The page states that the model is dedicated to Hirai Isao and is licensed under the Creative Commons Public Domain Dedication (CC0). The viewer loads the NASA body STL and separates the wing geometry to show the spacecraft's broad solar-array layout; the printed stand is omitted.
- **ISS:** The official NASA (A) entry links an actual `.glb` file. The downloaded file is 39,708 bytes and is browser-compatible with Three.js `GLTFLoader`; its Draco-compressed meshes are decoded with the locally bundled Apache-2.0 decoder in `public/draco/`.
- **NASA SLS Block 1:** The exact binary STL in NASA's `3D Printing/Space Launch System (SLS) Block 1` directory is loaded directly with the project's existing `STLLoader`. No conversion or source-asset modification was performed. It contains 274,432 triangles and has no embedded textures/materials, so the viewer applies a neutral display material. The launch-vehicle ID stays `heavy-launcher` to preserve saved records; its displayed name is now NASA SLS Block 1. Capacity and cost remain fictional game-balancing values. The repository credits NASA contributors collectively rather than identifying a model-specific author in the inspected directory; the source link and [NASA media usage guidance](https://www.nasa.gov/nasa-brand-center/images-and-media/) are shown in the game.
- **JWST:** The smaller (B) model is selected over the (A) model to avoid 1,600 separate mesh draw calls; the (B) GLB contains one mesh. Both are actual NASA-3D-Resources repository entries.
- **Parker Solar Probe and Juno:** The verified GLBs are loaded directly by the existing `GLTFLoader`. For Juno the (B) variant is chosen over the 9 MB (A) model.
- **Roman, Ingenuity, Landsat 8, and DSCOVR:** Their verified, compact GLBs are loaded directly by the existing `GLTFLoader`; campaign presets identify the supported destination proxy or simulated constraints.
- **Deferred candidates:** Curiosity's `.blend` is not loadable by the current Three.js viewer; its separate four-file printable assembly totals over 37 MB and does not include an assembled pose. Gateway's single Core GLB is about 63.2 MiB and represents only a core segment, so it was deferred rather than adding a large asset with incomplete station context.
- **Mission model limits:** The NASA models are visual references, not engineering geometry. Newly added spacecraft mass, power, cost, reliability, and mission thresholds are rounded gameplay abstractions. The builder does not simulate JWST's L2 operations/deployment, Parker's solar passages/thermal protection, Juno's Jupiter orbit insertion/radiation, or their mission-specific instrument performance. Juno uses a real Jupiter Horizons target and only preliminary transfer estimates; the Parker exercise is explicitly planning-only with Mercury as an inner-system proxy.
- **Launch/deployment animation:** The generic small/medium procedural vehicles animate a simplified lower-stage and attached-booster separation plus two procedural fairing halves. These are educational visual approximations, not exact real-world vehicle staging. The NASA SLS Block 1 model is a single STL mesh; its staging and fairing phases are explicitly labeled as simplified cues, and the source mesh is never split. Successful flights attach the selected spacecraft's actual local GLB or assembled STL model, separate it smoothly from the vehicle, show simulated communications initialization, and continue to a simplified destination-specific trajectory. Launch/deployment does not declare campaign success; the existing mission assessment still runs separately.
- **Small and medium launch vehicles:** These selections use the same detailed, procedural 3D vehicle assemblies in both the vehicle preview and launch sequence. They use metallic stage geometry, interstage rings, engine bells, and booster assemblies; they are generic game vehicles and do not claim to depict a specific real-world rocket.
- **Lunar Pathfinder:** The official NASA 3D Resources catalog was searched for a NASA/JPL downloadable 3D asset, and no model entry could be verified. This project therefore displays an unavailable state for this spacecraft instead of generating or reusing another model.

NASA source pages describe the Voyager and Cassini archives as freely downloadable model resources. The model pages do not provide an asset-specific license statement for every included mesh. This project keeps their NASA source links and credits NASA; any redistribution beyond this app should be reviewed against the current NASA media usage guidance and the individual asset page. Europa Clipper's model-specific CC0 terms are recorded above.

The NASA Eyes and [NASA 3D Resources](https://science.nasa.gov/3d-resources/) pages were also consulted as mission-visualization/catalog references. The 3D viewer loads only the selected spacecraft's local model assets, and never treats a mission visualization as a downloadable model unless a real model file is linked.

## Satellite observation imagery

Mission Control's Observation Console uses only target-appropriate sources:

- **USGS Landsat Collection 2 Level-2 Surface Reflectance:** 30-day date-window and bounding-box search through the [USGS Landsat STAC API](https://landsatlook.usgs.gov/stac-server/api.html), ending on the selected date. Supported Landsat 8/9 targets are named regions with a selected target center; returned scenes retain the actual provider acquisition timestamp, Landsat platform/instruments, processing level, cloud percentage, and pixel size only when those fields are present. A scene with 100% reported cloud cover is still shown with that metadata, not described as clear.
- **NASA GIBS:** a date-specific full-globe and regional [MODIS Terra Corrected Reflectance True Color](https://nasa-gibs.github.io/gibs-api-docs/) snapshot is requested for Earth. The separate regional layer is available in the archive details and is not a Landsat scene preview, not necessarily captured at a Landsat scene's acquisition time, and not an image from the simulated spacecraft. The globe layer and archive panel identify the requested imagery date and NASA provider.
- **Onboard camera Earth surface:** the React Three Fiber globe requests the selected date's full-globe [NASA GIBS Snapshot API](https://nasa-gibs.github.io/gibs-api-docs/) image for the `MODIS_Terra_CorrectedReflectance_TrueColor` layer and maps that fetched image onto the Three.js sphere. It is actual NASA MODIS reference imagery (with the selected layer date and provider identified in Mission Control), not a live feed or an image captured by the simulated spacecraft. Daily swath gaps and cloud coverage remain visible; missing pixels are not filled with invented imagery.
- **NASA EPIC:** date-specific natural-color thumbnails from the [EPIC API](https://epic.gsfc.nasa.gov/about/api). These are full-disk Earth images collected by EPIC on NOAA's DSCOVR spacecraft, not a game-spacecraft feed, high-resolution ground observation, or live feed.
- **NASA Image and Video Library:** NASA archive reference imagery for supported planetary targets, filtered to records whose title/description name the selected body, indicate an image/observation, and are not identified as artist concepts or renderings. NASA `date_created` is displayed as a catalog-record date rather than an acquisition time. The game does not claim these records were captured by the player's spacecraft.
- **No matching supported source:** show the target-body simulation scene and an explicit unavailable/reference status. Do not substitute a generic or unrelated image.

The same-origin observation endpoints are implemented by `server/observation-imagery.mjs` for Vite development and the production Node server. They use fixed HTTPS providers and a bounded 30-minute server metadata cache; API keys are not required. Landsat, EPIC, and NASA GIBS were live-checked during implementation. The USGS Landsat STAC search returns usable item metadata and a browse asset link, but its current preview URL responded with an EROS login page in direct checks; therefore, the console uses NASA GIBS for the separate archive map reference and retains Landsat scene metadata independently. The onboard camera fetches a date-specific global NASA GIBS MODIS texture and renders it on a real Three.js/React Three Fiber globe. Its deterministic synthetic orbit and manually controlled azimuth, elevation, and field of view are explicitly illustrative because Mission Control has no spacecraft orbit, attitude, altitude, pointing, or camera specification. NASA GIBS imagery, other archive imagery, and the simulation's separately acquired 128 MB data product are never conflated.

The mission briefing character uses NASA's Advanced Crew Escape Suit model from its official 3D Resources page and serves the local GLB copy at `public/models/advanced-crew-escape-suit.glb`. The briefing links back to NASA for attribution and source context. The resource page provides the downloadable GLB; no asset-specific license terms were verified, so this project does not claim a separate license and points users to the source page for current usage guidance.

## Editable assembly components

The Build / Edit controls add simplified, procedural viewer geometry for panels, antennas, engines, and instruments only when the player chooses to add them. These optional parts are design-prototype components, not additional NASA-sourced CAD assets. The imported spacecraft model, including its original solar panels, antennas, and instruments, remains visible in its default configuration. Lunar Pathfinder remains unavailable and does not receive a procedural substitute.

## Mission Control operations

The post-deployment Mission Control page reuses the selected spacecraft's catalog model and saved builder configuration. Its deterministic, persisted operations model derives power generation, instrument type/count, and communications capability from the launch record. Battery capacity (1,200 Wh), base/instrument loads, a 128 MB observation product, repeating observation/contact windows, and the instrument thermal response are illustrative game variables, not verified spacecraft specifications or real telemetry. Simulated battery, storage, temperature, link state, command outcomes, and event timestamps are generated from the shared operations state. There is no orbit propagation, altitude/velocity telemetry, fuel-consumption model, or real ground-station schedule. Completing deployment or the operations checklist does not replace the separate campaign mission assessment.
